# 中鱼钩 4/22 挂竿位扩展到全部钓法

Status: in-progress

## Problem Statement

中鱼后服务端补推的单钩 4/22 里，钩对象 `agedjipcnpe` 的 `hgaijieklek`（f09）此前只对
沉底族补挂竿位 `1024`（PR #387 限定版）。官方真服抓包现已覆盖全部钓法：挂竿位是
四钓法通用运行位，缺位时客户端钩实体不进搏鱼态——表现为浮漂无咬钩演出、左下角无
搏鱼指示（结算链 14/11→14/4→14/5 仍正常，鱼能上岸但全程无演出）。

## Solution

- `Push4_22Hook` 的挂竿位标记改为递归遍历（`markHookMounted`），同时兼容两种官方
  推送形状：单钩/单钩组 = 裸钩 `args("61")[131]`；串钩组/拟饵 rig =
  `ioombppcnlh` 嵌套容器（rig 本体 + 钩组件）。
- 14/11 中鱼分支对所有钓法补推钩 4/22 并挂位（`mounted=true`）。
- 海钓分支去掉 `marine_hook_item_sync` 门禁，14/11 无条件补推（官方口径）；14/15
  维持"鱼离场"语义默认关闭不变；14/9 分支保持原样（官方未见对应单钩推送）。

## Evidence（2026-11-10/11 官方服抓包，脱敏：仅协议字段级数据）

9 次中鱼钩 4/22 逐帧解码，`hgaijieklek` 全部 = 定义基值（钩 20992）| 1024 = **22016**：

| 钓法 | 样本（鱼种/重量） | 钩推送 | 钩 f09 |
|---|---|---|---|
| 沉底 rig_type=24 | 丁鱥 | 147B 裸钩 | 22016 |
| 浮钓 rig_type=1 族 | c.roach 680g / perch 221g / perch 119g | 147B / 146B / 146B 裸钩 | 22016 ×3 |
| 海钓 rig 50+ | merlang 252g（串钩）/ piksha 2975g（单钩） | 237B ioombppcnlh 嵌套 / 148B 裸钩 | 22016 ×2 |
| 路亚 rig 5~11 | perch 93g（脱钩）/ n.pike 4305g / b_gill 113g | 429B ioombppcnlh 嵌套（2 钩+拟饵参数）/ 240B 单钩变体 | 22016 ×3 |

- 14/14→14/11 自动上钩时延：底钓 +5.8s；浮钓 +11.6/+4.44/+8.4s；海钓 +0.46/+0.60s；
  路亚 +1.13/+0.32/+0.34s。中鱼钩 4/22 均在 14/11 后 ≈0.2~0.3s 内推送。
- 搏鱼期服务器每 2s 随客户端 14/8 回整套装备 4/22 快照（渔轮基值 23040|1024=24064，
  竿/线基值各异但运行位同样含 |1024），与钩 f09 语义一致。
- `[事实]` 挂竿位 1024 与钓法无关；`[推断]` 它是客户端钩实体进入搏鱼态的运行位，
  钓组形状（裸钩/嵌套）只影响包裹结构不影响 flags 语义。

## User Stories

1. 作为浮钓/路亚/海钓玩家，我在中鱼时希望看到与沉底钓一致的咬钩演出与搏鱼指示。
2. 边界：仅补齐 flags 与推送判定，不改钩对象结构、不改结算链、不动 14/15 门禁。

## Implementation Decisions

- `markHookMounted` 递归实现放 `profilebuild.go`，复用 `fieldIdxByCS` 定位
  `csStateEnum`；调用方语义不变（`mounted bool` 参数保留）。
- 测试覆盖裸钩/嵌套/nil 与非钩对象三种形状。

## Testing Decisions

- 单元测试：`hook_mounted_test.go` 断言 flags 20992→22016，嵌套容器内钩同构补齐。
- 回归口径：`TestCafeNativeFlowPaysAndPushesRemoval` 为既有基线失败，不计入本次。

## Out of Scope

- 不改海钓/路亚钩推送为嵌套容器形状（模拟器继续发裸钩；客户端接受度由实机回归
  验证，若某钓法演出仍缺再立 issue 对齐形状）。
- 不动 27.f19 与咬钩节奏（另案：f19 分钓法置值）。
