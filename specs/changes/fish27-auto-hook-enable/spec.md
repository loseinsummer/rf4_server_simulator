# 恢复客户端自动上钩判定

Status: done

## Problem Statement

服务器已经向客户端派发鱼，但静置钓组可能长期不进入上钩状态；玩家开始收线或抬杆后才立即咬钩，手竿也无法按客户端原生行为自动挂牢。

## Solution

鱼对象下发时启用客户端原生的自动上钩尝试，由客户端行为状态机继续决定触发时机和成功判定；不再要求玩家通过收线或刺鱼人为唤醒该分支。

## User Stories

1. 作为使用手竿或静置钓组的玩家，我希望鱼在满足客户端判定后能自行挂牢，以便不需要先收线才能看到咬钩。
2. 边界：发鱼、饵料匹配、鱼档位、嘬饵、跑鱼与结算规则保持不变。

## Implementation Decisions

- 修改 `internal/gameserver` 的 27 号鱼对象构造接缝。
- 保持对象类型、字段 op 和 14/14 响应形状不变，只修正 27.f19 的运行时语义。
- 不改表结构和存档；回滚只需恢复该字段值。
- 客户端版本基线为 4.0.25034。

## Testing Decisions

- 协议对象单元测试：对已校准鱼种和回退鱼种都断言 27.f19 为已知良好字面量 1。
- 实机测试：抛竿后不收线、不抬杆，观察客户端能否自行进入上钩或自然脱钩状态。
- 回滚生产改动后，27.f19 单元测试必须变红。

## Out of Scope

- 不调整咬钩延迟、发鱼权重、鱼口偏好、钩型软匹配和鱼的搏斗曲线。
- 不在服务端伪造 14/11 上钩请求。

## Further Notes

- `[事实]` 客户端 4.0.25034 的行为 105 读取 27.f19 作为自动上钩尝试的启用输入；本地实机把该字段固定为 1 后，手竿无需刺鱼即可自动挂牢。
- `[事实]` 当前服务端按鱼种和重量把该字段下发为远小于 1 的连续值。
- `[推断]` 该字段语义错配是静置时不自动上钩、动作后立即咬钩的根因。
- `[事实]` 2026-11-10 实机回归中，14/11 自动中鱼早于首次 14/9 抬杆 7 秒，确认不再依赖玩家动作触发。
